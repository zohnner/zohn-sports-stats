Team notes on this concept

Vera — UX

Job-to-be-done for the rail: "let me check my teams without picking a sport first." Right now that takes two decisions (pick sport, then find team); the rail collapses it to zero. State language for the chips reuses DESIGN.md's existing vocabulary exactly — live pink + pulse + text label, final = muted, upcoming = neutral pill with a time, never color alone. Empty state (no follows yet) shows the "+ Add team" affordance expanded to a short prompt, not a blank rail. Mega-menu keyboard behavior: Tab moves between pillar triggers, Enter/Space opens, Arrow keys move within an open panel, Esc closes and returns focus to the trigger — same pattern the existing .sub-nav-menu dropdown already uses, extended, not reinvented.

Kael — Design

Orange stays brand-only — active sport tab and active pillar underline are the only two new places it appears, both already-sanctioned "active nav" uses per DESIGN.md invariant #3. The live dot on a sport tab is --color-live, never orange, and never color-alone: paired with a visually-hidden "live game in progress" label for screen readers. Mega-panel is one visual recipe reused across all five sports — column count and content change, borders/spacing/type don't, which is the actual "compete with industry" move: consistency, not novelty. No licensed team logos here — real build uses the existing static/ESPN CDN logos already wired into every other component.

Axiom — Engineering

Everything here is reachable inside current constraints. Followed-teams rail reads AuthState.follows — already unified across all sports since 2026-08-05 (D-046 P5), so this is a new renderer against existing data, not a new data layer. Mega-menu is SUB_NAV_TABS's existing children shape, widened one level (children can carry a group + optional feature block) and rendered full-width instead of the current narrow position:fixed flyout — CSS + one rendering function change, not an architecture change. Live-dot per sport needs each sport module to expose a cheap hasLiveGame() read — MLB/NFL already compute this for their own ticker polling; NCAAF/NCAAB/WNBA would need the same one-line check added, not built from scratch. No new AppState shape, no new external domain, no CSP change.Feasible, not yet gated

Relay — Data

Live-state for the rail and the sport-switcher dots can ride the polling each sport module already runs for its own ticker/scores view — no new fetch cadence needed if a user is on-page, but the rail is visible from every view (including other sports' pages), so it needs its own light poll when the owning sport isn't the active one. Recommend a single shared 60s poll keyed to whatever's actually followed, not one poll per sport module — avoids five independent timers doing overlapping work.
